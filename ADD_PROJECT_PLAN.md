# План добавления нового проекта

Этот раздел — контекст для следующего AI-агента. Для каждого нового проекта нужны новые изображения, запись в `projects.ts` и обязательное добавление его фото/превью в арку проектов на первом экране через `src/content/arch.ts`. Не создавай отдельную страницу-компонент для каждого кейса и не переделывай весь сайт ради наполнения.

## 1. Прочитать контекст и проверить рабочее дерево

- Прочитай `AGENTS.md` и инструкции для изменяемых файлов. Перед изменением Next.js-кода сверяй нужные API с документацией в `node_modules/next/dist/docs/`.
- Выполни `git status --short`: здесь могут быть незакоммиченные правки владельца. Не откатывай их, не переформатируй несвязанные файлы, не создавай коммит или ветку без запроса.
- Для интерфейса используй `.agents/skills/design-taste-frontend/SKILL.md`, для React/TypeScript — `.agents/skills/ashel-front-style/SKILL.md`. При наполнении сохраняй текущие цвета, типографику и композицию.

| Что изучить | Где находится |
| --- | --- |
| Тип `Project`, категории и данные кейсов | `src/content/projects.ts` |
| Превью арки и порядок шести проектов | `src/content/arch.ts` |
| Реализация анимированной арки | `src/components/project-arch.tsx` |
| Карточки, фильтры и асимметричная сетка | `src/components/project-grid.tsx` |
| Общее содержимое страницы и модального окна | `src/components/project-detail.tsx` |
| Карусель постеров, жесты и геометрия | `src/components/poster-carousel.tsx`, `src/components/poster-carousel.module.css` |
| Прямая страница проекта | `src/app/projects/[slug]/page.tsx` |
| Открытие проекта поверх главной | `src/app/@modal/(.)projects/[slug]/page.tsx`, `src/components/project-modal.tsx` |
| SEO, превью ссылки и sitemap | `src/lib/project-metadata.ts`, `src/app/projects/[slug]/opengraph-image.tsx`, `src/app/sitemap.ts` |

## 2. Разобрать материалы и выделить суть

- Используй описание, вложения и ссылку пользователя как источники. Если Behance недоступен, работай с приложенными изображениями; не придумывай подробности недоступного кейса.
- Отдели короткую `summary` для карточки и метаданных от подробной `description`: задача, идея, визуальный подход и показанные решения. В `services` перечисли только подтверждённые виды работы.
- Не выдумывай клиента, результаты, метрики, сроки или участие в разработке. Сохраняй название и язык проекта.
- Для галереи отбирай ключевые изображения: общий вид, выразительные детали, мокапы и адаптив, если он есть. Не добавляй подряд все почти одинаковые кадры.

## 3. Подготовить локальные изображения

- Создай `public/images/projects/<slug>/`. Используй понятные имена латиницей: например, `cover.webp`, `arch.webp`, `mockup.webp`, `desktop-mobile.webp`.
- Храни изображения локально: сайт не должен зависеть от доступности Behance или временных URL вложений. По возможности используй WebP без заметной потери качества и без лишнего увеличения разрешения.
- Различай три назначения: `cover` — карточка и крупная обложка кейса; `arch.webp` — обязательное отдельное превью арки; `gallery` — изображения внутри кейса. Замена превью арки не должна незаметно менять обложку или галерею.
- Превью для арки готовь квадратным, **1:1**, с крупной, читаемой в маленьком размере композицией. Не перегружай мелкими деталями. Если пользователь дал готовое превью, используй его; генерация нового изображения — только по запросу, не вместо оригиналов работ.
- У каждого изображения в данных укажи содержательный `alt` и фактические размеры подготовленного файла `width`/`height`, а не размеры до конвертации. В путях `src` используй `/images/projects/...` без `public`.

## 4. Добавить данные проекта

Добавь объект в массив `projects` в `src/content/projects.ts`, ориентируясь на существующие реальные работы:

| Поле | Что заполнить |
| --- | --- |
| `slug` | Уникальный стабильный адрес латиницей через дефис |
| `title` | Название проекта |
| `category` | Одно значение из `categories`, кроме «Все работы» |
| `summary`, `description`, `services` | Короткое описание, суть кейса и выполненные работы |
| `cover` | Локальный путь, `alt` и размеры обложки |
| `gallery` | Изображения в осмысленном порядке; необязательный `title` используется для подписей карусели |
| `galleryLayout` | Опусти для обычной вертикальной галереи; `"carousel"` — для серии постеров |
| `url` | Реальная внешняя ссылка, если она есть; иначе опусти поле |
| `layout`, `background` | Тип карточки (`wide`, `portrait`, `medium`, `offset`, `last`) и подходящий фоновый цвет |

Не меняй существующие `slug`. Обычно добавляй запись в конец массива: порядок влияет на сетку и ссылку «Следующий проект». Для ссылок на проект используй getProject("<slug>"), а не индекс массива.

Маршрут `/projects/<slug>`, статическая страница, метаданные и превью ссылки строятся из данных автоматически. Реальная работа попадает в sitemap при настроенном `NEXT_PUBLIC_SITE_URL`; вручную перечислять новые маршруты не нужно. Счётчики проектов и фильтры также читают общий массив.

## 5. Сохранить свободную композицию и обновить арку

**Важное пожелание владельца:** карточки на главной должны располагаться свободно и асимметрично, с воздухом и разной высотой начала. Не ставь новую работу вплотную к предыдущей и не превращай список в плотную одинаковую сетку.

- За позиции всех карточек отвечает projectLayouts в project-grid.tsx: раскладка закреплена за slug. Задавай новой работе собственные ширину, горизонтальное смещение, строку и верхний отступ, сохраняя свободную композицию. Поле layout не задаёт позицию в общей сетке.
- Проверяй новую карточку вместе с соседними, а не изолированно. Корректируй размещение только при необходимости, не ломая композицию уже добавленных работ.
- **Каждый новый проект обязательно должен получить фото/превью в арке на первом экране.** Сейчас в src/content/arch.ts шесть реальных проектов, каждый повторяется дважды — всего 12 квадратиков. Сохраняй уникальные id. При добавлении новой работы согласуй расширение арки с владельцем; не заменяй существующие реальные работы без запроса. Для замены картинки меняй только image.
- Проверь фильтр нужной категории и «Все работы»: в отфильтрованном списке применяется отдельная двухколоночная раскладка без художественных смещений.

## 6. Выбрать и проверить галерею

Обычный кейс использует последовательную галерею. Для серии вертикальных постеров уже есть образец `/projects/poster-studies`, для квадратных баннеров — `/projects/vibe-coding-banners`, оба с `galleryLayout: "carousel"`; не создавай вторую реализацию с теми же возможностями.

Договорённости по карусели:

- Активный постер виден целиком, неактивные — узкие маски. Их текущая ширина ограничена 11% контейнера, 112 px и доступным пространством; на десктопе активный постер примерно вчетверо шире.
- Между **любыми** соседними элементами сохраняется зазор **16 px**, включая первый/последний слайд, переходы и перетаскивание. Шаг между двумя узкими элементами отличается от шага возле активного: не возвращай одинаковый большой шаг для всех центров — он создаёт пустоты на краях.
- Сохраняй управление мышью, свайпом, стрелками и клавишами ←/→, Home/End, подписи, счётчик, отключение крайних стрелок и поддержку reduced motion.
- Не отменяй горизонтальный жест из-за всплывающего `lostpointercapture` от дочерней кнопки: обработчик должен реагировать на потерю захвата самим контейнером. Вертикальный жест должен оставлять доступной прокрутку страницы.
- Геометрия использует фактические `width`/`height` изображений: проверены вертикальные постеры A-серии и квадратные баннеры. Размер активного кадра и шаг жеста согласованы с этими пропорциями; изображение вписывается целиком через `object-fit: contain`. Для горизонтальных работ или смешанных пропорций отдельно проверь размещение и высоту карусели, не обрезай оригиналы молча. Названия и доступные подписи переключаются на баннеры для категории «Баннеры».

`ProjectDetail` общий для прямого маршрута и модального окна: проверь оба способа открытия. Из списка проект открывается поверх главной; прямая ссылка и обновление страницы открывают самостоятельную страницу. Должны работать закрытие, Escape и история браузера.

## 7. Проверить результат и передать работу

- Проверь существование всех локальных файлов, размеры, `alt`, уникальность `slug`, правильную категорию.
- Убедись, что фото/превью нового проекта добавлено в арку на первом экране и корректно отображается. Без этого добавление проекта не завершено. Также проверь карточку с соседями, фильтрацию, прямую страницу, галерею и модальное окно.
- Коротко сообщи, какой проект и материалы добавлены, его маршрут и какие проверки действительно выполнены. Публикация, коммит и изменение остальных работ не входят в обычное добавление кейса.
